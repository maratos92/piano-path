# Roland FP-10 hardware acceptance procedure

**Current status: not performed.** An emulator or simulator cannot establish BLE radio, Android OEM timing, FP-10 pedal behaviour or reconnection reliability. Record phone model, Android/build version, WebView version, FP-10 firmware, pedal model and app commit before testing.

1. Install the debug APK on a physical phone. Turn on the FP-10 and its Bluetooth MIDI function according to Roland's manual. Close Roland/other MIDI apps. Pair from inside Piano Path, using Find piano. Verify the real device name and connected status. Test permission denial, later grant, Bluetooth disabled and, on API 26–30, Location disabled.
2. Diagnostics: play C4 softly/loudly. Verify MIDI pitch 60, distinct nonzero velocities, monotonically plausible nanosecond-derived timestamps, note-on/off and channel. Verify zero-velocity note-ons if the piano uses them.
3. Play 3-, 6- and 10-note chords, rolls over 50–180 ms, rapid repeated keys, overlapping hands and independently released chord tones. Verify every key release and that held/sounding displays agree with the instrument. Hold a key through another onset.
4. Sustain: hold CC64 down, release several notes and confirm held keys disappear while sounding keys remain. Lift the pedal and verify the sounding set empties. Keep a physical key held across pedal release. Record whether the connected pedal/FP-10 sends continuous or binary values; half-pedal artistry is not assessed.
5. Turn the piano off while notes/pedal are held. Confirm active practice stops, no keys remain stuck, status changes and retries back off. Power on and reconnect. Repeat 10 times, including Bluetooth toggling and leaving/re-entering range. Verify a new practice session starts at the selected passage rather than resuming uncertain state.
6. Import legally obtained MuseScore MusicXML and MXL versions of each Chopin waltz. Verify grand staff, key/time signatures, accidentals, tuplets, rests, chords, dotted rhythms, ties and fingerings. Check written order; unfold repeats for assessment. Select a short passage by ordinal measure and beat offsets.
7. At a slow fixed BPM, perform a reference passage correctly, then deliberately add wrong notes, omit chord tones, play early/late by approximately 100/250 ms and release keys early/late. Inspect per-note deviations, separate pitch/rhythm results and staff attribution. Compare against an independently timestamped MIDI recording or reference sequencer; human tapping alone is not timing ground truth.
8. Follow mode: pause for several seconds in a measure and resume. Confirm no timer-driven measure skipping. Wait mode: roll chords slowly and verify pitch completion advances without rhythm grading. Rhythm mode: miss notes and verify timed missing-note detection. Confirm repeated-pitch passages do not consume multiple score notes from one onset.
9. Loop a passage 20 times with a 4-beat count-in, pedal held at boundaries and varied endings. Verify pedal/key state resets, no previous errors leak into the next loop, history gains one record per repetition and automatic tempo changes occur only after the configured success threshold.
10. Calibrate through the actual phone audio path; compare manual offsets, phone speaker, wired and Bluetooth headphones. Record metronome scheduling jitter. Bluetooth audio latency can dominate MIDI latency and is not automatically measured.
11. Scales: test left/right/both, one/two octaves, minor descent and thumb crossings. Confirm the app says recommended fingering, never detected fingering. Sight reading: exercise every level/time signature, preview option and hand selection. Verify history categories and simulated-input labels.
12. Rotate a phone in practice, try landscape, a tablet, large system fonts and dark mode. Airplane mode with Bluetooth re-enabled must still support scores/training/history. Import a malformed/oversized/unsafe MXL and verify a useful error without a crash.

Capture failures with reproducible passage boundaries, BPM, score-file hash and anonymized diagnostic events. Do not publish imported copyrighted scores or device MAC addresses in public issue reports without permission.
