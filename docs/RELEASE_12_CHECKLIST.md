# Release 12 — continuous cursor, notation and useful progress

Version 0.6.0-dev.2, Android build 12. No account/cloud/new Room schema.

- **Cursor is the release gate:** position geometry covers every graphical measure, including missing staff/note entries; one requestAnimationFrame owner moves through gaps independently of incoming note packets. Native transport supplies rate, stops on pause/count-in/rest, snaps on seek/loop/layout and clamps at the passage end. WAIT remains event-driven and animates actual advances instead of inventing tempo. Real-renderer test checks empty staff/measure geometry, continuous frame updates without new packets, pause and circular pin. Frame rate on a physical device still needs acceptance testing.
- Circle cursor pin stays at viewport top; loop edge grips are narrow, rounded vertical controls in the middle of each edge. Toolbar loop icon sits beside Played notes, after falling-scale controls. User-facing saved passages are called loops; duplicate selection button removed. Four-second countdown is independent of tempo, with optional scale/fade animation. Sheet is the default view.
- Studio replaces MIDI Studio; shorter centered labels and a mixer-style icon. Listening uses a different icon. Practice setup removes fixed-width framing. Progress distributes tabs on tablets and removes the leading scroll-tab gap on phones. Settings no longer duplicates Connect piano under note names.
- Shared native music staves use unmodified Bravura/OFL glyphs, including empty Studio staff. This replaces manually sketched flags/rests. Paused expected keys retain more of their fill.
- Progress categories: Overview, Pieces, Scales, Sight reading, Listening. Each has a seven-day chart. Only completed repetitions and active explicit Finish actions create scored attempts; opening/reviewing scores, empty count-in finishes, cancellations and free play do not. Note accuracy = matched / (expected + extra); on-time = expected notes within inclusive ±tolerance / expected, missing notes get zero. WAIT has no timing percentage; FOLLOW is labelled performance-aligned. New records use scoring version 2 and optional onTimeCorrect JSON; old composite rhythm scores are not relabelled. Listening precision is correct complete submitted answers / attempts. Daily charts aggregate counts; improvement comparisons retain identical context.
- Listening setup collapses after start. Every submitted attempt remains in its fixed staff column; chords share that column even when entered sequentially. Answer stays hidden until guessed or attempts expire. Keyboard shows numbered attempt marks and a revealed-answer dot. No hidden answer enters a WebView.
- Requested illustrated decoration is not replaced by another hand-drawn motif: an export-ready transparent-art prompt is supplied separately. Existing frame options remain optional; Plain preserves a clear reading surface.

## Validation

Use exact-head CI reports before merge/publication. Native tests cover fixed countdown at two tempos, default Sheet, scoring/no-scoring boundaries, metrics and backward JSON reads, immutable ear history and hidden-answer rules. Browser suites cover real OSMD scrolling, loop dragging, width reflow and the continuous gap cursor. Hardware BLE/USB output/echo, MIDI latency, actual tablet ergonomics and perceived smoothness remain owner acceptance checks. No claim of guaranteed FPS or Play approval.
